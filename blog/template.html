How to use this file

Copy this page, delete the sections you do not need, and write into the skeleton. Every component below is defined in assets/css/blog.css, which all posts share. Do not add per-post <style> blocks: if a post needs something new, add it to blog.css and render an example here so the next post finds it.

House rules for the prose. Sentence case in headings. Straight quotes. Colons and periods instead of em dashes. No metaphors that do not carry information. State the number, then say what it means.

The three-stage spine

Every findings post runs on the same argument: what is broken, what we changed, what the change bought. Open with the flow so a reader who stops after ten seconds still leaves with the shape of it, then repeat the stage number on each section header.

  1. Problem

    The failure, stated as a measurement rather than an impression. One number belongs here.

  2. Intervention

    What changed, and explicitly what was held fixed. A reader should be able to rebuild it.

  3. Evidence

    What the change moved, with the sample size visible and the comparison that settles it named.

01

Problem

What is broken

Body copy is 17px at 1.7 line height and runs the full 1000px column. Use bold for the claim a skimming reader should catch and monospace for identifiers, commands, and field names. Keep paragraphs to four or five sentences. Lists sit narrower (--list); plots and tables narrower still (--fig), centred on the same axis.

A lead-in holds the question the post answers, or the single sentence you want quoted.

An h3 opens a block inside a stage

Use h3 when a stage has two or more distinct moves. Use the mono h4 below it for a label that is closer to a caption than a heading.

An h4 labels a sub-point

It sits tight against the paragraph that follows so the two read as one unit.

  • Plain lists take ul.plain. Use them for unordered facts.
  • Use ol.principles instead when the order carries meaning.
  1. Ranked first. The numbered list is for priorities and procedures, where position one outranks position two.
  2. Ranked second. Bold the label, then explain it in one sentence.
  3. Ranked third. Three to five items. Past that, use a table.

02

Intervention

What changed

Callouts

Caveat A warn callout carries a limitation the reader needs before they read the next number: unequal sample sizes, a metric that does not mean what its name suggests, a result that did not replicate.
Held fixed An ok callout confirms the controls. In a comparison post, list here everything that was identical across arms.

Assembly diagram

For anything composed from parts: a prompt built from layers, a pipeline built from stages, a payload built from blocks. Keep the top-to-bottom order of the source blocks identical to the order inside the payload. Mark the blocks that are yours with class="a".

Citations

Mark the claim with <a class="cite"> pointing at the entry's id, and give the entry a matching link back. Both directions resolve: the marker jumps down to the source1, and the return arrow in the list jumps back to the sentence that cited it. Cite the primary source rather than a summary of it2, and cite a number only where a reader would otherwise have to take it on trust3.

03

Evidence

What it bought

Composition: stacked bar

For "where does the whole go", where the parts sum to 100%.

Magnitude: horizontal bars

For "which is bigger". Set each .fill width inline as a percentage of the largest value.

Trend: inline SVG

Anything the CSS plots cannot express is hand-written SVG inside the same .fig-frame. Keep the viewBox wide (roughly 640×220), give it a role="img" and an aria-label that states the values, and use the token colors so it matches the rest of the page.

Two figures side by side

Wrap a pair in .fig-grid when they are read together. They stack under 760px.

Tables

The table is the right form once there are more than two numbers per row. Right-align numbers, give them td.num for tabular figures, and mark arms with .cell-a / .cell-b. The caption states the takeaway, not the contents.

04

Limits

What this does not show

Close every findings post with the limits, before the conclusion rather than after it. List the sample sizes, the conditions that were not varied, and the claims the data does not support. A reader who finds an unstated limitation stops trusting the stated numbers.

Footnote text uses p.note. Put the exact run counts, dates, and commit or job ids here.
